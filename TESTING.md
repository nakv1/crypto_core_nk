# Проверка CryptoCore

## Проверка генератора через NIST STS

### Зачем

NIST Statistical Test Suite (STS) - набор из 15 статистических тестов.
С помощью него проверялись байты из `cryptocore.csprng.generate_random_bytes`.

Такая проверка помогает найти заметные статистические закономерности в случайных данных, но не доказывает криптографическую стойкость генератора.

### Окружение

- NIST STS 2.1.2;
- WSL 2;
- Ubuntu 24.04.5 LTS;
- исполняемый файл:

```text
/home/nak/nist-sts/sts-2.1.2/sts-2.1.2/assess
```

Отдельной документации README, PDF или DOC в установленной поставке STS не оказалось, поэтому параметры запуска были проверены по исходникам программы, в основном по `src/assess.c` и `src/utilities.c`.

### Запуск

NIST STS запускался из его корневого каталога:

```bash
./assess 1000000
```

Число `1000000` означает длину одной проверяемой последовательности в битах.

Ответы на вопросы программы:

```text
0
/mnt/c/Users/nak/cryptocore_sts/cryptocore_sts_data.bin
1
0
80
1
```

По порядку это означает:

- читать данные из файла;
- использовать указанный путь;
- выбрать все 15 статистических тестов;
- оставить параметры тестов по умолчанию;
- обработать 80 последовательностей;
- использовать бинарный формат входных данных.

В результате файл размером 80 000 000 бит был разделён на 80 последовательностей по 1 000 000 бит.

Использовались стандартные параметры:

- Block Frequency: `M = 128`;
- Non-overlapping Template: `m = 9`;
- Overlapping Template: `m = 9`;
- Approximate Entropy: `m = 10`;
- Serial: `m = 16`;
- Linear Complexity: `M = 500`.

Перед запуском каталог результатов `experiments/AlgorithmTesting` не содержал старых файлов, поэтому результаты разных запусков не смешивались.

### Как читать итоговый отчёт

В отчёте STS используются два разных показателя.

1. **PROPORTION** показывает, сколько последовательностей прошли конкретный тест.

   Отдельная последовательность считается прошедшей, если её `p-value` не меньше `0.01`.

   В контексте STS ориентир из m3 `p-value >= 0.01` прежде всего относится к этому уровню.

2. **P-VALUE** в итоговом отчёте проверяет, насколько равномерно распределены p-value всех последовательностей.

   Для этого показателя STS использует другой порог:

```text
P-VALUE >= 0.0001
```

Минимальная допустимая доля прошедших последовательностей рассчитывается по формуле NIST SP 800-22:

```text
(0.99 - 3 * sqrt(0.99 * 0.01 / m)) * m
```

Для 80 последовательностей получается примерно:

```text
76.53
```

Для 52 последовательностей:

```text
49.33
```

В STS 2.1.2 рассчитанный порог хранится в переменной типа `int`, поэтому дробная часть отбрасывается. Фактически программа использует значения 76 и 49.

В итоговом отчёте это выглядит так:

```text
The minimum pass rate for each statistical test with the exception of the
random excursion (variant) test is approximately = 76 for a
sample size = 80 binary sequences.

The minimum pass rate for the random excursion (variant) test
is approximately = 49 for a sample size = 52 binary sequences.
```

Если строка не проходит один из критериев STS, программа помечает её символом `*`.

### P-VALUE ниже 0.01

У пяти строк из 188 значение `P-VALUE` оказалось ниже `0.01`.

Это не считается провалом STS, потому что для этого показателя используется порог `0.0001`.

Эти значения приведены отдельно:

- Non-overlapping Template, шаблон 34 (`001001011`): `0.006196`, `80/80`;
- Non-overlapping Template, шаблон 54 (`010000111`): `0.001859`, `79/80`;
- Non-overlapping Template, шаблон 138 (`111101010`): `0.006196`, `79/80`;
- Non-overlapping Template, шаблон 145 (`111111000`): `0.003577`, `77/80`;
- Random Excursions Variant, состояние `+1`: `0.002374`, `51/52`.

Все эти значения выше штатного порога STS `0.0001`.

### Random Excursions

Для Random Excursions и Random Excursions Variant использовались только 52 последовательности из 80.

Эти тесты работают только с последовательностями, в которых набралось достаточное число циклов случайного блуждания.

Для последовательности длиной 1 000 000 бит требуется не меньше 500 циклов. Этому условию соответствовали 52 последовательности.

Оставшиеся 28 последовательностей эти тесты не использовали. Само по себе это не считается отказом теста.

NIST SP 800-22 рекомендует использовать не менее 55 последовательностей для проверки равномерности p-value.

В данном запуске подходящих последовательностей было 52, поэтому значения `P-VALUE` для Random Excursions и Random Excursions Variant нужно оценивать с учётом этого ограничения.

Это относится в том числе к значению:

```text
0.002374
```

для состояния `+1` в Random Excursions Variant.

### Вывод

Все 15 тестов NIST STS были выполнены.

В итоговом отчёте нет строк со звёздочкой `*`, все 188 строк прошли критерии, которые использует STS.

Явных статистических проблем в данных, полученных через `cryptocore.csprng.generate_random_bytes`, тесты не обнаружили.

При этом один прогон NIST STS помогает выявить статистические проблемы, но не доказывает безопасность или криптографическую стойкость CSPRNG.
